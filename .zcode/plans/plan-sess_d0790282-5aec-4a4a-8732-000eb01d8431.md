# 纯 API 化改造：彻底移除 Electron，重建为 Node 宿主渲染框架

## 目标

把仓库从"Electron 桌面应用 + 附带 API"重构为**纯 Node 渲染服务器**：无头 Chrome（Playwright）作为渲染工作进程，Node 宿主提供 HTTP API、静态资源托管、桥接层和 ffmpeg 编码。本地（Windows + Intel 核显）完成全部可测项，远端 Linux + NVIDIA 仅剩 NVENC 一项待部署验证。API 契约不变（端点、端口 9881/9882、apifile 产物），**AstrBot 插件零改动**。

## 保留 / 删除清单

**删除**：`src/main/`（Electron 主进程）、`src/preload/`、`electron.vite.config.ts`、`electron-builder.yml`、`dev-app-update.yml`；依赖中的 `electron`、`electron-updater`、`electron-builder`、`electron-vite`、`@electron-toolkit/*`、`@pixi/unsafe-eval` 之外按需清理；窗口类 IPC（resize、save-window-size、select-story-file、SaveDialog 系列 handler）随主进程一起消失。
**抢救复用**（从旧代码迁移进新结构）：`VideoApiServer`（去 Electron 后端点/队列/限流/清理原样保留）、`TTSServiceServer`（本就是纯 Node）、IpcHandler 里的 ffmpeg 全套函数、`StorySchema`/`IpcResponse` 等 common 类型、整个 renderer 渲染与导出子系统。

## 新结构

```
src/host/            纯 Node 宿主（tsc 编译 → out-host/，node 直接运行）
├─ main.ts           组装 + 优雅退出
├─ config.ts         env：MSS_PORT(9881)/MSS_TTS_PORT(9882)/MSS_HOST/MSS_OUTPUT_DIR(apifile)
│                    MSS_RESOURCE_DIR(resources/builtin)/MSS_CONFIG_DIR(user-configs)
│                    MSS_WORKERS(1)/MSS_FFMPEG_ENCODER(auto|nvenc|qsv|amf|libx264)/MSS_FFMPEG_PATH
│                    MSS_BROWSER_CHANNEL(msedge→chrome→chromium 降级)/MSS_BROWSER_EXECUTABLE/MSS_CHROME_ARGS
├─ servers/          VideoApiServer.ts（重构：无 Electron、直接对接渲染池）、TTSServiceServer.ts（平移）
├─ bridge/           invoke 通道(9个)、二进制写盘端点(append-to-file/write-temp-file)、
│                    tts/translation 代理、WebSocket（下行 api:start-export / 上行 export-result、on-error）
├─ pool/             Playwright 渲染池：启动 flags（Linux 加 --use-angle=gl，--autoplay-policy=
│                    no-user-gesture-required 等）、WebGL renderer 探测（进日志+health）、
│                    页面常驻复用、崩溃重建
├─ static/           / = out/webrenderer、/resources/builtin/*、/apifile/*（防路径穿越）
└─ ffmpeg.ts         自 src/shared/ffmpeg.ts 引用（从 IpcHandler 抢救的函数全集 + 编码器可选参数）

src/webrender/       网页渲染工作进程（vite 构建 → out/webrenderer/）
├─ index.html        精简 DOM（#app + 字体 css + live2d 两个核心 script，无配置面板/导出弹窗）
└─ src/bootstrap.ts  安装 browser-bridge 后再加载 App

src/renderer/        渲染引擎（保留），纯 API 化裁剪：
├─ src/utils/ResourceUrl.ts   统一资源 URL（/resources/builtin/...），替换 5 处 mss://
├─ app/App.ts                 裁剪为纯 API：保留 runApiExport、setupApiExportListener、
│                             loadAndApplyConfigForApiExport、初始化链；删除 UI/播放/选story 代码
└─ browser-bridge.ts          实现 window.electron.ipcRenderer 同形接口（invoke→HTTP、事件→WS）、
                              window.api.getFolder —— renderer 业务代码零改动
```

构建系统：`vite.config.ts`（webrenderer）、`tsconfig.host.json`（host，含 common/shared）。package.json 重写：删 electron 系依赖与脚本，新增 `playwright`、`ws`；脚本 `typecheck`、`build`（web+host）、`start`、`e2e`。`.github/workflows` 同步更新（不再产出安装包）。

## 实施阶段

1. **Phase 0 基线**：工具链检查（node/pnpm/ffmpeg——缺失则 winget 安装或 ffmpeg-static 注入 `MSS_FFMPEG_PATH`；浏览器用系统 Edge/Chrome，否则 `npx playwright install chromium`）；`git add -A && git commit` 建立基线（仓库当前零提交）。
2. **Phase 1 抢救与迁移**：抽取 `src/shared/ffmpeg.ts`（checkFFmpeg/detectAvailableGpuEncoder/getGpuEncoderArgs/runFfmpegWithProgress/apiConvert/apiMerge，API 路径编码器从写死 libx264 改为可配置，默认不变）；迁 VideoApiServer（去 Electron、去掉窗口 restore/focus 与 --api-only 分支）、TTSServiceServer 到 `src/host/`。
3. **Phase 2 renderer 纯 API 化**：webrender 入口 + browser-bridge + ResourceUrl 替换 + App.ts 裁剪（以 typecheck 为安全网）。
4. **Phase 3 宿主组装**：config/static/bridge/pool/main + package.json 与构建脚本重写 + 删除 Electron 残留文件。
5. **Phase 4 本地测试**：
   - T1 `pnpm typecheck` + `pnpm build` 全绿；
   - T2 宿主启动 → `/api/v1/health` 返回 worker 就绪数 + WebGL renderer 字符串（本机预期 `ANGLE (Intel...`，**不得出现 SwiftShader**）；
   - T3 端到端：`scripts/test-export.mjs` 读取 `resources/builtin/multi-character-demo.sekai-story.json` POST `/api/v1/export` → 轮询 → ffprobe 断言 MP4（h264/1280×720/时长>0/含音轨/帧数>0），打印 MediaRecorder codec、ffmpeg 编码器、耗时；
   - T4 队列串行 2 任务 + `MSS_WORKERS=2` 并行各验一次；
   - T5 无 TTS 服务环境导出必须成功（验证容错路径）；
   - T6 编码器矩阵：libx264 vs qsv（本机 ffmpeg 支持则测），NVENC 留待服务器。
6. **Phase 5 部署文档**：`docs/host-deployment.md` —— Linux 裸机依赖（Node+Chrome+ffmpeg+NVIDIA 驱动，**无需 Xorg**）、env 表、systemd 单元、NVENC 验证三步（`ffmpeg -encoders|grep nvenc`、health 的 renderer 字符串、`nvidia-smi dmon`）；README 增补纯 API 用法。

## 风险与预案

| 风险 | 预案 |
|---|---|
| 无头 Chrome 里 MediaRecorder/captureStream 异常 | 回退到帧捕获管线：bridge 补 write-frame-batch 通道，帧序列直通 ffmpeg 合成 |
| 开源 Chromium 缺 H.264 编码 | 优先系统 Edge/Chrome；即便 vp9 也有 ffmpeg 转码兜底 |
| 无头 WebGL 落到 SwiftShader | health 暴露 renderer 字符串报警；flags 调优手册写入部署文档 |
| App.ts 裁剪误伤导出依赖 | 裁剪以类型检查+T3 端到端为验收；裁剪前先跑通再删 UI |
| TTS/翻译代理 CORS | 全部走宿主代理端点（与原 IpcHandler 语义一致：30s 超时等） |

## 交付物

新约 14 个文件（host×8、webrender×3、shared/ffmpeg、ResourceUrl、test-export.mjs、部署文档），修改约 8 个（renderer 数处、package.json、workflows），删除 Electron 全套。完成后 `pnpm build && pnpm start` 即是可直接部署的纯 API 渲染框架。
